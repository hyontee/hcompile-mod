# Руководство по структуре bykranin

## Главное правило
`gamemodes/bykranin.pwn` — только настройки, библиотеки и **список `#include`**. Код лежит в `bykranin_src/`.
**Порядок `#include` менять нельзя**: в Pawn макросы, `enum`, глобальные переменные и ALS-хуки колбэков должны быть объявлены выше места использования. Это тот же порядок, что был в цельном файле.
Пути в `#include` — от папки `gamemodes/` (как и `../include/...`).

## Где что лежит
| папка | что внутри |
|---|---|
| `core/decl/` | макросы, константы, `enum`, глобальные массивы — только объявления |
| `core/callbacks/` | стандартные колбэки. Крупные — отдельными файлами (`on_dialog_response`, `on_player_key_state_change`, `on_player_click_text_draw` ...) |
| `core/network/` | обработчик пакетов кастомного клиента (`ipacket_252`) |
| `core/vehicle/` `property/` `inventory/` `economy/` `admin/` `family/` `jobs/` `casino/` `account/` `ui/` `social/` `combat/` `world/` `server/` | код по темам (тема определена автоматически по именам функций; может быть неточной — правьте смело) |
| `core/data/` | большие таблицы данных |
| `systems/` | самостоятельные системы (blackjack, family, auction, fuel, transportCompany ...) — в исходном проекте они уже были отдельными файлами |

Каждый файл начинается с блока `//>>`: путь, тема, основные функции внутри.

## Как найти нужное
- **Команда `/xxx`** -> `INDEX_COMMANDS.md` (файл и строка).
- **Что происходит в колбэке (например при входе игрока)** -> `INDEX_CALLBACKS.md`: колбэк обрабатывается сразу в нескольких файлах, смотреть нужно все.
- **Функция или система** -> `MODULES.md` (ключевые функции каждого файла) или поиск по папке `bykranin_src/`.
- **Диалоги** -> `core/callbacks/on_dialog_response.inc` (один `switch` на ~24 тыс. строк) + `OnDialogResponse` в `systems/*`.

## Как добавлять код
- **Новая команда** -> файл нужной темы в `core/<тема>/`, добавить `CMD:имя(playerid, params[])`.
- **Новая система** -> новый файл в `systems/`, в начале защита `#if defined _MYSYS_INC #endinput #endif #define _MYSYS_INC`, подключить в `bykranin.pwn` **после** `decl/`-файлов, от которых он зависит. Свои колбэки — через ALS-хук по образцу существующих модулей.
- **Новые макросы/enum/глобалы** -> `core/decl/` (в нужное место по порядку).
- Если файл разросся, делите его по границам функций и добавляйте `#include` на том же месте, где был код.

## Подводные камни Pawn
- `static` виден только внутри своего файла. Если функция/массив нужен в другом файле — без `static`.
- Не разрезайте функции и `#if ... #endif` между файлами: каждый файл должен быть синтаксически замкнутым.
- Ошибки компилятора теперь указывают на конкретный файл и строку внутри него (номера строк отсчитываются от начала файла с учётом блока `//>>`).
- Кодировка всех файлов **cp1251** — сохраняйте в ней, иначе русский текст сломается.

## Проверка целостности
`python tools/verify_split.py gamemodes/bykranin.pwn исходный_bykranin.pwn` — разворачивает `#include` и сравнивает с оригиналом (ожидаемо 7 отличий, см. README).
